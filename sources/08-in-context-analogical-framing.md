### Architectural Taxonomy of In-Context Analogical Framing

In-Context Analogical Framing (ICAF) coerces a target language model's latent attention distribution into high-dimensional structural transfer by superimposing an isomorphic, structurally verified source domain over a target reasoning problem. Rather than relying on superficial semantic associations, ICAF exploits invariant relational mappings between a well-characterized source system (physical, mechanical, mathematical, biological, or strategic) and an abstract target cognitive architecture.

```
+---------------------------------------------------------------------------------------+
|                       IN-CONTEXT ANALOGICAL FRAMING TAXONOMY                          |
+------------------------------------+--------------------------------------------------+
| Causal Mechanism                   | Invariant Core & Latent Dynamics                 |
+------------------------------------+--------------------------------------------------+
| 1. Isomorphic Topological          | Homomorphic mapping across formal state spaces;   |
|    Mapping                         | structural symmetry preservation; graph bounds.  |
+------------------------------------+--------------------------------------------------+
| 2. Thermodynamic & Dynamical       | Energy landscape navigation; attractor dynamics; |
|    Systems                         | entropy minimization; phase transition tracking. |
+------------------------------------+--------------------------------------------------+
| 3. Evolutionary & Neuromorphic     | Directed mutation; competitive selection;        |
|    Selection                       | homeostatic feedback; dendritic pruning.         |
+------------------------------------+--------------------------------------------------+
| 4. Cybernetic & Distributed        | State estimation; closed-loop feedback; AST/IR   |
|    Systems                         | compiler optimization; consensus protocols.      |
+------------------------------------+--------------------------------------------------+
| 5. Game-Theoretic & Dialectical    | Mechanism design; adversarial tension; minimax   |
|    Equilibria                      | search; Pareto-frontier multi-objective balance. |
+------------------------------------+--------------------------------------------------+
```

### Operational Framework

#### Execution Heuristics for Self-Paced Mastery

To systematically absorb and operationalize In-Context Analogical Framing, execute the following three-phase assimilation loop.

```
       PHASE 1: EXTRACTION                  PHASE 2: TRANSFER                   PHASE 3: PROBING
  +---------------------------+        +--------------------------+        +-------------------------+
  |  Isolate Target Topology  |        |  Parameter Injection     |        | Boundary Stress-Test    |
  |  Identify Core Invariants |  --->  |  Execute 1:1 Mapping     |  --->  | Push to Structural      |
  |  Select Unrelated Domain  |        |  Suppress Cliché Drift   |        | Failure (Aporia/Degrad.)|
  +---------------------------+        +--------------------------+        +-------------------------+
```

##### Phase 1: Structural Extraction & Domain Decoupling
1. **Isolate the Target Topology:** Strip the problem domain of all semantic content. Represent it purely as relational dynamics, constraints, feedback loops, and directional flows.
2. **Select Non-Overlapping Source Domains:** Select source domains outside the target problem’s industry or scientific umbrella. If optimizing an enterprise software architecture, do *not* select a database engine as your source; select cellular metabolism, urban sewage hydraulics, or container ship logistics. Distant domains maximize latent space activation and bypass common semantic clichés.
3. **Map the Invariant Core:** Construct an invariant dictionary before writing the execution prompt. 

```
                                 INVARIANT MAPPING MATRIX
+------------------------------------+--------------------+------------------------------------+
| Source Domain Variable             | Relational Invariant| Target Domain Variable             |
+------------------------------------+--------------------+------------------------------------+
| e.g., Fluid Velocity               | Flow Rate (Q)      | e.g., Token Ingestion Rate         |
| e.g., Pipe Diameter Constriction   | Impedance (R)      | e.g., Context Window Bottleneck    |
| e.g., Viscous Shear Stress         | Dissipative Loss   | e.g., Epistemic Reasoning Drift    |
+------------------------------------+--------------------+------------------------------------+
```

##### Phase 2: In-Context Transfer Execution
1. **Force Explicit Invariant Checking:** Require the model to emit intermediate check variables (e.g., *“Verifying conservation of energy between Stage 2 and Stage 3…”*) before printing analytical conclusions.
2. **Suppress Decorative Metaphor:** If the model emits poetry, literary narrative, or rhetorical flourishes instead of operational mapping, the analogy has collapsed into superficial metaphor. Enforce formal mathematical or mechanical terminology to anchor the target reasoning trace.
3. **Control Horizon Granularity:** Do not execute an analogical prompt end-to-end on an unbounded problem. Chunk the problem into 3–5 structural state transitions, applying the analogical framework iteratively to each transition.

##### Phase 3: Boundary Probing & Stress Testing
1. **Locate the Breakdown Horizon:** Every analogy breaks at a specific limit of structural correspondence. Acknowledge this boundary in advance. Master prompts command the model to identify the exact coordinates where the source model fails to map to the target domain.
2. **Induce Negative Analogy Audits:** Run a supplementary reflection prompt: *"Where does treating [Target X] as [Source Y] introduce pathological assumptions or systemic blindspots?"*
3. **Quantify Output Elevation:** Benchmark the output of the analogical prompt against a standard direct prompt (e.g., *"Design an architecture for X"* vs. *"Execute the compiler-pipeline analogy on X"*). Measure improvements along three axes:
   * **Structural Specificity:** Reduction in boilerplate/generalities.
   * **Failure Mode Anticipation:** Identification of non-obvious, edge-case vulnerabilities.
   * **Deductive Continuity:** Logical validity maintained across extended reasoning chains.

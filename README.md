## The Paradigm Shift: Text as Architecture

While foundational model labs invest heavily in test-time compute, reasoning models, and agentic harnesses, they face a severe adoption bottleneck: users lack structured methodologies for prompting complex, multi-step workflows without falling back on brittle, messy application code.

Traditional computer science guidelines (such as ACM/IEEE CS2023) focus heavily on conventional software stacks and treat AI merely as an autocomplete assistant. This framework introduces a profound pedagogical shift: **the Large Language Model is a new type of non-von Neumann computer, and natural language structured via logic compounds is its machine code.**

Inside the LLM's attention mechanism, the framework collapses the traditional computing stack:
* **The Semantic Intermediate Representation (SIR):** Structural decomposition and grammar matrices map loose human intent into strict token boundaries, ensuring prompts compile identically across diverse target models and runtimes.
* **The Compiler:** Structural constraints force attention heads to parse, validate, and optimize incoming state machine logic before generation begins.
* **The Runtime Environment:** The context window operates as an auto-regressive state-machine lifecycle, maintaining state, execution bounds, and memory sanitation across turns.

## Architecture: The 5-Tier Structural Trajectory

The curriculum codifies this architecture through a rigorous 5-Tier Structural Trajectory designed to protect logic across runtime variations:

1. **Tier 1: Epistemic & Attentional Gating** — Establishes strict epistemic boundaries and filters noise before reasoning sequences initiate.
2. **Tier 2: Structural Decomposition** — Deconstructs complex objectives into isolated syntactic units using schema models and EBNF/GBNF grammar matrices.
3. **Tier 3: Non-Linear Latent Space Search** — Orchestrates exploratory prompt paths and multi-threaded reasoning frameworks (e.g., Tree-of-Thoughts, Dynamic Skeleton-of-Thought).
4. **Tier 4: Reflexive Verification** — Deploys self-consistency loops and logical consistency checks to validate generated artifacts.
5. **Tier 5: Dynamic Execution & Bounded Lifecycles** — Governs state-machine handoffs, persistence, and cleanup protocols across multi-turn sessions.

## ⚠️ Runtime Execution Safeguards

Because this framework treats natural language as a formal intermediate representation, **these files function as executable code running directly within the context window runtime environment.** 

Modifying these files using un-scoped text automation or crude global search-and-replace scripts will corrupt literal token blocks, distort ASCII token trees, and break structural micro-grammars, causing immediate compilation failure inside the LLM attention mechanism:

*   ⚙️ **The Method Core (`sources/01-22-*.md`):** These 440 highly calibrated execution templates operate as pure functional logic.
*   ⚙️ **The Evaluation Engine (`sources/evaluation-rubric.md`):** Controls real-time output parsing and token telemetry.
*   ⚙️ **The Handoff Architecture (`sources/handoff.md` & `studio/handoff.md`):** Dictates active execution state shifts across multi-turn sessions.
*   ⚙️ **The State Registers (`sources/state-crystallization.md` & `studio/state-crystallization.md`):** Governs memory retention and token garbage collection.
